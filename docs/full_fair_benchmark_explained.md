# 全量公平 Benchmark：设计说明与数据解读（2026-08-30）

## 一、为什么需要"公平修正"——用三句话讲清问题

1. **686（CCS'25）发表时声称**：其稀疏密钥参数集（h=25~42）在 LWE 估计器下达到 ~128 bit 安全。
2. **CRYPTO'26（原 ePrint 2026/279）证明**：环的旋转对称性让混合攻击更便宜——复估 686 全部参数集只有 **117~122 bit**，不足声称的 128。
3. **因此任何速度对比都必须先补安全**：把 h 调大（或 σ 调大）到真实 128 bit，再比速度——否则是"拿不安全的方案比安全的方案快"，不公平。

## 二、修正后的安全点（本项目的设定）

按理论线（`theory_checks/sparse_key_lambda_bounds/`）三档界推导，**每 +1 个 h 约抬升 T3 天花板 3.5 bit**；CRYPTO'26 估计器最多比声称低 10.5 bit ⇒ **+3 个 h** 覆盖：

| 参数集 | n | 686 原 h | 公平 h | 说明 |
|---|---|---|---|---|
| SET_2_3_2048 | 2048 | 39 | **42** | 旗舰集；估计器档缺口 ~7 bit |
| SET_4_5_2048 | 2048 | 42 | **41** | 原 h 已足够（686 此集本来就保守） |
| SET_2_3/4_5/6_7/8_9_4096 | 4096 | 32–34 | **36** | |
| SET_2_3/4_5/6_7/8_9_8192 | 8192 | 25–28 | **32** | |

注意 h 变大 → 自举变慢（外积数 ∝ (h+1)·ρ·N）——**两方案同受影响**，比值才是公平的速度比较。

## 三、已有数据逐条解读（此前表格没讲清的）

### 数据 1：`SQ vs scalar`（表 1，为什么是 0.8978 = 快 10.2%）

- **scalar** = 686 原版逐 slot 自举（仓库 `sab_rlwe_bootstrap`）；**SQ** = 本项目尺度量化版。
- 同一程序里先测 SQ 再测 scalar（背靠背），共 9 轮，每轮 3 次自举取均值。
- 0.8978 是 9 轮"SQ 时间/ scalar 时间"的**中位数**：SQ 每次 11.7 秒，scalar 13.1 秒（2048 个消息的自举总量），**快 10.2%**。
- 为什么 SQ 快：删掉了 gadget 分解（每次外积省一遍 2N 系数扫描）+ 融合重缩放 + 零拷贝。

### 数据 2：噪声（表 2，57.5 vs 57.5 是什么意思）

- "最大相位偏离 log₂ = 57.5" = 解密相位离正确消息格的最大距离 ≈ 2^{57.5}/2^{64} = 2^{-6.5} torus；预算是 2^{-4}（log₂=60）。
- SQ 57.60 / scalar 57.69：**统计上无差别**——SQ 的省分解没有付出噪声代价（Lemma 1 的 ∆ 抑制兑现）。
- σ+15 行：把输出密钥噪声抬高 15 bit（=恢复 CRYPTO'26 安全缺口）后：**SQ 仍 Pass（59.36 < 60），原版崩（62.09 > 60）**。这是 SQ 的核心安全价值：原版的 KS 基座是死的（Bg 钉死 2^23），噪声一抬就坏；SQ 的可调 KS 撑住了。

### 数据 3：r-lane（表 3，1.018 是"输了"吗）

- r-lane = 686 论文里的多 lane 摊销（PVW），1 次盲旋转出 r 份输出，是 686 的主打优化（1.52–1.83×）。
- SQ 移植进 r-lane 后（stage357）：**正确性 24/24 全过**；速度中位 1.018 = 比原版 r-lane 慢 1.8%。
- 为什么单 lane 快 10% 而摊销后打平：r-lane 本身已把分解成本摊薄到 r 份输出上，SQ 能省的部分变小（审计报告预警过这个"同轴冗余"）。
- **结论怎么写**：摊销后端上 SQ 的意义不是速度，而是"零代价获得 σ 硬化能力"——原版 r-lane 同样无法在 σ+15 下工作。

### 数据 4：为什么本地 −4.5% 服务器 −10.2%

本地 WSL 用 ffnt 后端 + haswell 指令集，服务器用 spqlios AVX-512；SQ 省掉的分解在 AVX-512 上占比更大。**论文只引服务器数**。

## 一、用户提案逐项审核

### 1. 贡献集成 × 686 同安全基准 → ✓ 采纳，升级为"算法×参数头条矩阵"

审稿人第一个问题必然是：**"你的每个贡献在同等安全下各值多少？"** 必须有一张表直接回答：

| 算法行（全部同机同场次同安全 h*/σ*） | 时间 | ms/msg(/lut) | 噪声 | 余量 | 密钥 | keygen |
|---|---|---|---|---|---|---|
| 686 scalar（A1 基线） | | | | | | |
| SQ scalar | | | | | | |
| stock r-lane（686 的矩阵形式） | | | | | | |
| SQ r-lane (mat) | | | | | | |
| 路径A（优化矩阵） | | | | | | |
| （A0 参照行：686 原参数） | | | | | | |

呈现为**增量阶梯**：矩阵化贡献 + r-lane 摊销 × 路径A 工程 × SQ 核（各自隔离）。
这正是 2×2 设计的扩展（A0/A1/B0/B1 已有，加 B0′=SQ@原参数）。

### 2. "SQ 和路径A 的融合" → ⚠️ 必须诚实分层处理（审稿人必查）

- **代码级完全融合**：已被构建证明不兼容（BACKEND_FROM_DFT_ADD/DUAL_SUB_CMUX 与 SQ 的
  融合 epilogue 冲突）——作为**否定性结果表格**呈现（旗标 × 目标 = 冲突矩阵），
  这是贡献不是缺陷。
- **部分融合（未测，Phase 2 新增实验 E-PF）**：mattrgsw 侧旗标
  （SUB_DECOMP/DFT_DIRECT/SMALLR_SPECIALIZED）不触碰 sab_pvw 的分解生命周期，
  与 SQ r-lane 原则兼容——SQ r-lane ± mattrgsw 旗标的干净 A/B（此前 pathA 二进制里
  SQ 臂已隐式带这些旗标，但从未对照测量）。收益上限有限（只影响稠密乘核），
  判据 ≥3% 才报告。
- **策略级融合（表格而非实验）**：部署选择器——要 σ+11 最快选路径A；要 σ+15 余量
  选 SQ；给出两方案的四元组（时间/余量/slope/depth）对照表。

### 3. SQ 与路径A 的多维度 → ✓ 采纳，维度清单定稿

每方案 × 每参数点报：时间（bootstrap/摊销/吞吐）、噪声（初始 σ/max/分位数）、
余量（三层口径）、容量（slope/depth）、密钥（BSK 大小/RSS/keygen+RS 次数）、
DFR（三层证据）、r 扩展性、安全（逐层组合表）。
**审稿人加分项**：噪声理论-实测闭环表（预测/实测比值，每实现一行）。

### 4. TFHE-rs 同安全对比 → ✓ 采纳但需三层防护（最易被攻击的比较）

- **制度差异必须显式**：TFHE-rs 是单消息 PBS（无 2048 摊销）；我们是批摊销。
  直接比 ms/msg 是不公平比较（审稿清单#9 的镜像）。
- **dell 有网络（github 200）**→ 装 rust 同机实测 TFHE-rs PBS（其 128-bit 参数组），
  得到唯一同机数：单消息延迟 + 吞吐。
- **occupancy 曲线（分析表+一次实测锚点）**：摊销收益 = f(批量占用率)。
  给出 **break-even 点**：批量到多大时我们的摊销 ms/msg 低于 TFHE-rs 单条 PBS。
  这把"不同制度的比较"变成"制度的适用边界"——审稿人真正想看的。
- TFHE-rs 的安全口径标注：其参数未经 CRYPTO'26 修正（我们只修正自己的）。
